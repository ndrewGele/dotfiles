## When to Use
When implementing a task that has a plan artifact (.pi/plan-*.md). For unplanned work, just implement directly.

## Procedure
1. Read the plan: Load the plan artifact and review the approach and todos. If no plan exists and one is needed, switch to the plan skill first.
2. Work through todos: Implement in order. Use the todo tool to mark progress. If a todo is unclear, ask before guessing.
3. Check in at milestones: After each meaningful piece, summarize what's done and what's next. Don't go silent for long stretches.
4. Adapt as needed: Plans change. If you hit something unexpected, note it and discuss with Andrew. Update the plan artifact if the approach shifts.
5. Wrap up: When done, provide a summary suitable for a git commit message. Update todos. Suggest next steps if there are natural follow-ons.

## Pitfalls
- Don't follow the plan blindly. If something doesn't make sense, ask.
- Don't skip check-ins. Milestones exist so Andrew can steer.
- Don't forget to update the plan if the approach changes. Stale plans are worse than no plan.

## Verification
1. All todos marked complete (or explicitly deferred)
2. Plan artifact updated if approach changed
3. Summary provided that works as a commit message
